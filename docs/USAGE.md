[返回项目首页](../README.md)

## 选择路线和配速

- 地图上方可以切换 **涌泉湖—院训路环线**（沿校园步道和院训路，基准单圈约 742.6 米）和 **开发区校区田径场**（约 421.5 米）。两条路线均可选择方向。每圈在原路线附近平滑调整走线，最后一圈在目标里程处结束。
- 默认勾选 **随机起点**。控制台按路线长度抽取一个位置，地图的「起点」、雷电定位和 FIT 的首个采样点使用同一坐标。修改配速或切换方向会保留这个位置。点击 **重新生成** 会换一个起点。取消勾选可回到原来的固定起点。更换起点后，在 Keep 开跑前重新点 **定位起点**。
- 输入的配速为全程平均值。起步、途中和收尾的变化会平滑衔接。控制台显示模拟双脚步频和每一步的长度，两者与当时的速度对应，例如 6:00 分/公里、每分钟 170 步约为每步 0.98 米。
- **离线预演 ×20** 可在电脑上查看路线、实时配速和累计模拟步数。默认 3 公里的预演约需 54 秒。同一次生成的预演、实时回放和 FIT 导出使用相同的轨迹和步频。
- **箭头跟随跑向**：电脑地图的当前位置改为方向箭头，按实际生成的走线计算朝向，随机起点、顺逆时针和每圈偏移都适用。在新版 Keep 计步窗口中，定位和方向同步更新；转弯平滑旋转，跨越正北时走最短转角，暂停时保留朝向。重新定位起点会立即对齐新方向。

## 用 Keep 的「户外跑步」记录

1. 选中装有 Keep 的雷电 14 实例。列表为空时，点 **选择目录**，选中含有 `ldconsole.exe` 的安装目录，然后点 **刷新**。
2. 保持 **同步跑步计步** 勾选，点 **定位起点**，再点 **打开 Keep 计步窗口**。首次使用会通过本地 ADB 在所选实例安装随程序附带的安卓组件。窗口底部有 **返回** 和 **关闭计步窗口** 两个按钮。
3. 在这个窗口内进入 Keep 的 **运动 → 户外跑步**。保持默认的 **与 Keep 起停联动** 勾选，先在电脑点 **实时回放**，控制台会定位到起点并等待；随后在 Keep 点 **GO**。识别到跑步页面后自动开始，等待期间不增加里程和步数。Keep 需要精确位置和「身体活动」权限；已经允许的身体活动权限会保持原设置。
4. 在控制台或 Keep 中暂停、继续，都能同步定位和计步。到达目标里程或在控制台结束时，会尝试自动暂停 Keep，并显示确认结果。随后可在 Keep 中结束并保存运动，看完详情再关闭计步窗口。

联动已适配本机 Keep 9.1.110 的户外跑步页面，只识别计步窗口中的 Keep 控件。回放期间保持跑步页面可见。离开页面或锁屏后持续 3 秒无法识别，回放会停止并提示检查。取消勾选联动时，仍可沿用手动开始、分别暂停的方式。如果提示旧版计步窗口，先关闭雷电中旧窗口，再从新版控制台重新打开。控制台的 **上次回放** 可查看该实例最近一次成功发出的定位、步数进度和结束状态，程序重新打开后仍可查看。

计步窗口使用 Android 14 的虚拟设备接口，在窗口内提供逐步触发、累计步数、三轴加速度，以及磁场、重力、旋转向量、地磁旋转向量和兼容方向传感器。各方向传感器采用一致的设备姿态；Keep 可用加速度与磁场计算朝向。定位和计步读取同一条时间线，电脑休眠后不会各自补算跳跃进度。定位通道连续 3 秒无响应时，两路一起停止；电脑休眠后回放暂停，需要检查后继续。组件无需 root，使用实例里已安装并登录的 Keep。控制台显示模拟值，详情页显示 Keep 统计的结果。

升级方向功能后，需要先关闭雷电中的旧计步窗口，再用新版控制台点 **打开 Keep 计步窗口**，程序会更新安卓组件。普通 Keep 窗口和仅 GPS 回放不提供虚拟指南针；这项方向同步需要使用计步窗口。

2026-11-15 已在本机 Keep 地图确认方向箭头随输入朝向变化。独立 Android 采样在 30 秒内读取 150 组数据，覆盖正北两侧和多个转向；计步期间，加速度与磁场重建的朝向相对重力与磁场重建结果最大偏差约 **1.83°**。逐步检测与累计计数均为 **56 步**。这是方向传感器的短测，不代表全程跑步的 GPS 里程误差已消除。

2026-11-14 在本机 Keep 完成了默认 **3 公里 / 18 分钟**的完整回放，终点自动暂停。Keep 保存结果为 **2.95 公里**、训练时长 **18:00**、总时长 **18:03**、平均配速 **6:06**。平均步频 **169 步/分**，最高 **173**、最低 **120**，平均步幅 **0.96 米**。控制台累计发送 **3,057 步**。

实时定位目标间隔为 **0.5 秒**，按发送时刻取坐标。当前 Keep 配速图仍有少量尖峰，单点步幅为 **0.04–1.99 米**，记录里程比控制台少约 50 米。雷电定位接收与 Keep 统计仍有误差，瞬时配速和步幅的平滑性还有改进空间。

## 导入 FIT 文件

1. 在 **FIT 文件导入** 页选择 **保存单个 FIT**，或 **发送单个 FIT**。
2. 在 Keep 打开 **运动数据文件导入**，从 **下载 / Download** 选择对应时间的 `DUT-EDA-sim-…fit`。部分版本的入口位于 **我的 → 总跑步 → 右上角更多 → 运动数据同步**。[参考项目的导入图解](https://github.com/EmberCollective/CampusRunning/blob/7f7d8d21cb2f6a5fa45f8f2a6103ac8d029c92d0/guied.md)
3. 文件导入的记录在 Keep 中显示 **数据导入**。这个来源由 Keep 的导入流程决定。要从 Keep 开始一场运动，请使用上一节的「户外跑步」。

FIT 按当前设置生成完整的一次跑步，以导出时刻为终点。每秒写入位置、距离、速度、步频、累计跨步和步长。每公里分段和全程汇总都写入累计跨步和不足一个跨步的余量。FIT 中一个完整跑步跨步对应左右脚各一次落地。控制台显示双脚合计的模拟步数，Keep 是否展示该字段可在导入后的详情页核对。

新版 3 公里样例用时 **18:00**，三个整公里分别为 **6:04、6:00、5:56**。逐秒解码得到双脚步频约 **167–172 步/分**，单步长度 **0.96–1.00 米**，全程 **3,057 步**。[新版 3 公里样例](../样例/DUT-EDA-smooth-3km.fit)

### 按日期批量导入

1. 在主界面选好路线、距离和配速，打开 **FIT 文件导入 → 批量日期导入**。点 **日历多选** 可以选择多个日期，按住 Shift 再点一天可选中一整段。也可直接粘贴日期，或读取日期列表 TXT / CSV。例如输入「2026-11-01 至 2026-11-05，2026-11-08」会生成六条记录。重复日期合并为一条。
2. 选择随机时段，查看每一天的起跑和结束时间。默认 **下午或晚上**，从 **14:00–18:00** 或 **18:30–21:30** 抽取，**晚上占比**默认 50%，可填 0–100。另有白天、上午、下午、晚上、自定义，以及 **工作日晚 / 周末午后**（按周一至周五、周六日判断，不含法定调休）。采用北京时间，整段运动都落在所选时段内。星期复选框和 **排除日期** 可以筛选日期，排除日期也支持范围。
3. 双击一行或点 **编辑当天**，单独改距离、配速、起跑时间、路线、方向和随机起点。编辑后默认锁定当天；锁定行不受重抽或时段修改影响。可重抽选中的日期，也可重抽全部未锁定行，重抽时间会保留该天走线。列表中的参数就是导出参数，手动编辑的时间优先于随机时段。
4. 点 **保存批量 ZIP**，或 **发送 ZIP 到雷电**。一天一个 FIT，传到雷电的 ZIP 位于所选实例的 **下载** 目录。列表会标出未来时间和曾经成功导出的日期；再次导出前可据此检查，或在排除日期中去掉重复日期。
5. 在 Keep 中打开 **我的 → 全部数据 → 运动数据同步 → 运动数据文件导入 → 选择文件**，直接选整个 ZIP。当前雷电里 Keep 的导入页支持一个 ZIP 包含多条运动，单包上限为 **500M**。导入后的记录会显示「运动数据文件导入」。

批次自动保存在 `%LOCALAPPDATA%\KeepEDA\batches.sqlite3`。关闭再打开会恢复上次草稿，包括逐天参数、时间、起点种子和锁定状态；不因主界面重新抽取起点而改变。**新批次**使用主界面当前设置。**导出历史**可恢复最近 100 次保存或发送的批次，并查看目标文件位置；失败或取消的任务不记为成功。历史只记录本工具的保存、发送动作，不代表已经导入 Keep。

2026-11-14 已将一个包含两条 0.5 公里运动的 ZIP 实际导入 Keep。详情页分别显示 **11 月 13 日 19:10–19:13** 和 **11 月 14 日 09:20–09:23**，均为 **3:00 / 6:00 每公里 / 170 步每分**，平均步幅分别 **0.97 米、0.98 米**。两条记录在列表中保留各自日期，并标记运动数据文件导入。

## 连接与排查

| 现象 | 操作 |
| --- | --- |
| 找不到雷电 | 手动选择安装目录，也可将环境变量 `LDPLAYER14_HOME` 设为该目录。 |
| 实例的定位被其他控制台占用 | 切回使用同一实例的校园跑窗口。定位或打开计步窗口完成后即可重试。等待 GO 时点 **取消等待**，已暂停或回放中点 **结束**。若已关闭原窗口，等「正在关闭」消失再重试。 |
| Keep 地图停在旧位置 | 确认选中的实例索引，在 Android 中开启系统定位并授予 Keep 精确位置，再点 **定位起点**。 |
| Keep 箭头方向没有更新 | 使用新版控制台打开的计步窗口。若提示缺少方向传感器，关闭旧计步窗口后重新打开，再点 **定位起点**。 |
| 计步窗口未打开 | 检查雷电是否运行 Android 14、是否开启本地 ADB 调试，解锁模拟器后再点 **打开 Keep 计步窗口**。Keep 退出后也可用这个按钮重新打开。 |
| 普通 Keep 已经计时，控制台仍为 00:00 | 先在普通窗口处理当前运动并返回 Keep 首页，再从电脑打开 **Keep 计步窗口**。在底部有 **关闭计步窗口** 按钮的页面进入户外跑步，电脑点 **实时回放** 后再点 **GO**。 |
| Keep 实时记录的步频很低或步幅为空 | 核对 Keep 的「身体活动」权限，确认跑步是在底部有 **关闭计步窗口** 的窗口内开始的。回放状态栏应显示 **Android 步数**。雷电普通窗口使用加速度时，Keep 可能严重少计步数。 |
| 只想回放定位 | 取消 **同步跑步计步**，点 **打开 Keep** 进入普通窗口。 |
| FIT 发送失败 | 在雷电设置中开启本地 ADB 调试，按雷电提示重启后重试。也可先保存到电脑，自行传到模拟器。 |
| 回放中实例断开或定位阻塞 | 定位和计步一起停止，保留已显示的里程。检查 Keep 中的当前运动后，再决定是否开始新一轮。 |

距离在每次启动时回到 3.00 公里。路线、方向、平均配速和实例选择保存在 `%LOCALAPPDATA%\KeepEDA\settings.json`。定位使用雷电的 `locate`，计步窗口通过本地 ADB 连接至所选实例。关闭窗口会释放虚拟屏幕、传感器和该窗口建立的设备关联。普通窗口支持雷电的 `call.gravity` 加速度接口。[雷电官方命令文档](https://help.ldmnq.com/docs/LDPlayer-ming-ling-hang-kai-fa-zhe-shi-yong-shuo-ming/n)

## 运行源码与生成 EXE

在项目根目录运行以下命令。Windows 下使用含 Tk 的 Python 3.10 或更新版本运行。桌面版 EXE 已包含运行时和 FIT 依赖。

```powershell
py -3 -m pip install -r requirements.txt
py -3 app.py
py -3 -m unittest discover -s tests -v
```

随源码附带的 `data/keepeda-sensors.apk` 可直接使用。若修改安卓组件，可在配置 JDK 17、Android SDK Platform 34 和 Build Tools 35.0.0 后运行 `.\android\build.ps1` 重新编译。以下命令生成 `dist\KeepEDA.exe`。

```powershell
py -3 -m pip install pyinstaller==6.22.3
py -3 -m PyInstaller --onefile --noconsole --name KeepEDA --icon data/keepeda.ico --add-data "data;data" --add-data "licenses;licenses" --copy-metadata fit-tool app.py
```

## 数据与实现来源

- 地图和路线采用 WGS-84 坐标。湖区地图位于 `data/dut-lake.geojson`，田径场位于 `data/dut-eda.geojson`。地图数据来自 © OpenStreetMap contributors，按 ODbL 1.0 提供。[湖边步道](https://www.openstreetmap.org/way/1076344125) · [院训路](https://www.openstreetmap.org/way/1076344094) · [田径场跑道](https://www.openstreetmap.org/way/1076344140) · [地图数据许可](https://www.openstreetmap.org/copyright)
- 配速与 FIT 导出的思路参考 CampusRunning。开发区校区定位及调用雷电的思路参考 school-runing-dut。桌面控制器、路线生成、计时与传感器回放均独立编写。[CampusRunning](https://github.com/EmberCollective/CampusRunning) · [school-runing-dut](https://github.com/tianxingleo/school-runing-dut)
- FIT 编码使用 BSD-3-Clause 许可的 fit-tool，许可证随源码和程序提供。[fit-tool](https://github.com/shaonianche/python_fit_tool) · [Garmin FIT Activity](https://developer.garmin.com/fit/file-types/activity/)
- 方向传感器按 Android 的坐标轴和旋转向量约定实现。[Android 方向计算](https://developer.android.com/develop/sensors-and-location/sensors/sensors_position#sensors-pos-orient) · [Android 传感器类型](https://source.android.com/docs/core/interaction/sensors/sensor-types#rotation_vector)
